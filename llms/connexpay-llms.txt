## API Reference
- [Create Sale](https://docs.connexpay.com/reference/getting-started-with-your-api.md): The Create Sale Endpoint is used by acquiring clients. The Sale transaction is used to create a sale for your consumer. You can create a credit sale or an ACH sale (ACH sales apply to US Clients only). A credit sale will charge a consumer's credit card. The consumer's credit card will be authorized immediately when the Sales request is received and will automatically settle/batch that same night. In other words, this one Sale request is just like running an AuthOnly and a Capture in one request.You can postpone charging the consumer's credit card by providing a date in the 'ActivationDate' of your request. Doing so will delay the authorization and charge to the consumer's credit card until that future date.An ACH sale will create an ACH transaction that will debit the consumer's bank account. ACH sales received prior to 3:00 PM EST will process overnight. ACH Sales received after 3:00 PM EST will process the following night.
- [Void](https://docs.connexpay.com/reference/void.md): This endpoint creates a void.
- [Return](https://docs.connexpay.com/reference/return.md)
- [Cancel](https://docs.connexpay.com/reference/cancel.md): The Cancel route should be used in the event the entire trip/booking (sale & purchase) require cancellation. In this case, the traveler/cardholder would be due a refund from the sale and the Virtual Card would be terminated to prevent the travel supplier from authorizing the Virtual Card.
- [Auth Only](https://docs.connexpay.com/reference/auth-only.md): The Auth Only Endpoint is applicable to acquiring clients.  Call Auth Only when you want to process an Authorization only, which will not settle until it's Captured.  We do not allow you to Capture an Authorization after 5 business days have passed.Calling this endpoint will authorize the card, however, it will not be settled until the [Capture endpoint](https://docs.connexpay.com/reference/capture) is called. Authorizations expire after 5 days.
- [Capture](https://docs.connexpay.com/reference/capture.md): Call this endpoint to Capture an Authorization so that it settles
- [3DS Authentication](https://docs.connexpay.com/reference/3ds-authentication.md): This endpoint can be used for obtaining 3D Secure Authentication separate from the Create Sale or Auth-Only calls.  This is recommended for our US and CA clients.
- [Get 3DS Status Group](https://docs.connexpay.com/reference/get-3ds-status-group.md): This endpoint returns the 3D Secure status of an authentication when a device fingerprint and/or cardholder challenge are required for 3D Secure Authentication.
- [Update Delayed Sale](https://docs.connexpay.com/reference/update-delayed-sale.md): Updates the sale amount or activation date on a delayed activation sale.
- [HPP (Hosted Payment Page)](https://docs.connexpay.com/reference/hosted-pay-page.md)
- [HPP Token Request](https://docs.connexpay.com/reference/hpp-token-request.md)
- [Decline Codes - Sales](https://docs.connexpay.com/reference/decline-codes.md): Decline Codes for US, EU, and CAD clients are separated into three tables within this page. The identified codes are API sales authorization responses that exclude any risk-related declines that may be configured with Equifax or your risk provider.
- [Client Self-Service Funding](https://docs.connexpay.com/reference/merchantselfservicefunding.md): Use this endpoint to fund or withdraw your merchant cash balance with your merchant bank account.
- [Client Funds Transfer](https://docs.connexpay.com/reference/client-funds-transfer.md): Use this endpoint to transfer funds between your merchant cash balances within the same Corporate entity.
- [Create Checkout Session](https://docs.connexpay.com/reference/createcheckoutsession.md): Creates a new secure checkout session for payment processing.  The session contains all payment details for a transaction and expires after 60 minutes for security. Returns a checkout session ID that can be used with the ConnexPay SDK for frontend payment processing.  ## Key Features - Secure session management with 60-minute expiration - Support for multiple tender types (Credit, ACH, GooglePay, ApplePay) - Comprehensive customer and transaction data support - Device authorization validation - Risk analysis and fraud prevention integration  ## Usage Flow 1. Create checkout session on your backend 2. Pass the returned `checkoutSessionId` to your frontend 3. Use the session ID with ConnexPay SDK to render payment form 4. Process payments through the SDK using the session
- [Issuing Token](https://docs.connexpay.com/reference/issuing-token.md): API requests require a combination of assigned user name, password, and successfully generated authentication token. The received token is valid for 24 hours from issuance and may be used for all requests during its lifespan.
- [Issue Card](https://docs.connexpay.com/reference/issuecard.md): Use this endpoint to issue virtual cards associated with a credit or ACH sale. Do not use this endpoint if you fund your virtual cards from cash and therefore don't have an associated sale. If you aren't sure which Issuance API to use, please contact your client support representative.
- [Issue Lite](https://docs.connexpay.com/reference/issuelite.md): For our lite clients, we provide the ability to issue a VCC (Virtual Credit Card) via API without the requirement to process a sale first.  If you aren't sure which Issuance API to use, please contact your client support representative.
- [Issue Lodged Card](https://docs.connexpay.com/reference/issue-lodged-card.md): Use this endpoint to create a Lodged Card
- [Update Card](https://docs.connexpay.com/reference/updatecard.md)
- [Update Lodged Card](https://docs.connexpay.com/reference/update-lodged-card.md)
- [Resend Transmission](https://docs.connexpay.com/reference/resendtransmission.md): This endpoint resends payment information to recipient. Or returns a URL you can use within your application to direct a user to a visual representation of the virtual card.
- [Update Virtual Card with Delayed Activation](https://docs.connexpay.com/reference/update-delayed-card.md): Request this endpoint to update the activation date or card limit of a virtual card with a future activation date.
- [Card Booking](https://docs.connexpay.com/reference/card-booking.md): Use the Card Booking endpoint to send booking details for existing virtual cards that were issued without them. This supports workflows where a travel management company issues the card before the booking details are finalized. Booking details cannot be updated once successfully submitted. The Sertifi platform is used to automate the hotel booking authorization through this request. Contact your ConnexPay representative before use as fees will be applied and configuration is required.
- [Currency and Region Codes](https://docs.connexpay.com/reference/currency-and-region-codes.md): Valid currency and region codes to use with the currencyCode and region fields in Issue Card & Issue Lite endpoints.
- [Create User Defined Parameter](https://docs.connexpay.com/reference/create-user-defined-parameter.md): Use this endpoint to create User Defined Parameters to associate with your PayOuts.
- [Update User Defined Parameter](https://docs.connexpay.com/reference/update-user-defined-parameter.md): Use this endpoint to update a previously created User Defined Parameter. Only the name and maximum length may be updated.
- [Delete User Defined Parameter](https://docs.connexpay.com/reference/delete-user-defined-parameter.md): Use this endpoint to delete a created User Defined Parameters. Once a User Defined Parameter has been used with a PayOut or EmailTemplate, it may not be deleted.
- [Stop Payment Service](https://docs.connexpay.com/reference/stoppaymentservice.md): Adds a card to the black list. Need to provide the card guid and other mandatory fields applicable for VISA or MasterCard.
- [Create merchant payor](https://docs.connexpay.com/reference/merchantpayor_createpayor.md): Create a payor for a merchant. For Authentication with this API, you must first obtain a token through https://docs.connexpay.com/reference/issuing-token.
- [Get Merchant Payor](https://docs.connexpay.com/reference/merchantpayor_getpayor.md): Get a merchant payor by guid.  For Authentication with this API, you must first obtain a token through https://docs.connexpay.com/reference/issuing-token.
- [Update Merchant Payor](https://docs.connexpay.com/reference/merchantpayor_updatepayor.md): Update a merchant payor by guid. For Authentication with this API, you must first obtain a token through https://docs.connexpay.com/reference/issuing-token.
- [Delete Merchant Payor](https://docs.connexpay.com/reference/merchantpayor_deletepayor.md): Delete a merchant payor by guid. For Authentication with this API, you must first obtain a token through https://docs.connexpay.com/reference/issuing-token.
- [Decline Codes - Purchases](https://docs.connexpay.com/reference/decline-codes-purchases.md): Decline Codes for Purchase Card Authorizations
- [Issue ACH](https://docs.connexpay.com/reference/issue-ach.md): This endpoint creates an ACH Credit payment. May be used by USD merchant accounts only.
- [Issue ACH Lite](https://docs.connexpay.com/reference/issue-ach-lite.md): This endpoint creates an ACH Credit payment that does not have an associated sale. This allows ConnexPay Lite clients to submit the issue payment call only. May be used by USD merchant accounts only.
- [Search Settlements](https://docs.connexpay.com/reference/search-settlements.md): This endpoint searches for Virtual Card Settlements.
- [Available Funds](https://docs.connexpay.com/reference/available-funds.md): Use this endpoint to pull details regarding your Available Funds like cash balance, Available to Authorize (ATA) or Available to Issue (ATI), and the details that make up the final number.
- [Purchase Event History (Replay Webhooks)](https://docs.connexpay.com/reference/purchase-event-history.md): Call this endpoint to receive VCC, Lodged Card, Physical Card or ACH purchase events either by unique Guid or for a specified date range. If you subscribe to webhooks and are concerned you may be missing events, this endpoint can retrieve past events.
- [Submit a Payment Instruction](https://docs.connexpay.com/reference/createpaymentinstruction.md): Used to create a new payment instruction. The request must include all required fields such as clientId, clientPaymentId, payee details, payment amount, and currency code. Optional fields like paymentDueDate and user-defined fields may also be included.
- [Get Funding Status](https://docs.connexpay.com/reference/getfundingstatus.md): This endpoint retrieves the funding status updates for a payment request identified by the client ID and client payment ID.
- [Get Payment Status](https://docs.connexpay.com/reference/getpaymentstatus.md): This endpoint retrieves the payment status updates for a payment request identified by the client ID and client payment ID.
- [Void a Payment Instruction](https://docs.connexpay.com/reference/voidpaymentinstruction.md): This endpoint voids a payment instruction identified by the client ID and client payment ID.
- [Sales Chargebacks](https://docs.connexpay.com/reference/sales-chargebacks-1.md)
- [Reporting Token](https://docs.connexpay.com/reference/reporting-token.md): Reporting API requests require a combination of assigned Bridge user name, Bridge password, and a successfully generated authentication token. The Bridge credentials used are assigned separately from the Purchase and Sales API credentials. The received token for Reporting is valid for 60 minutes from issuance and may be used for all requests during its lifespan. Note: This endpoint is only valid in the Production environment.
- [Get UATP Transactions](https://docs.connexpay.com/reference/uatptransactions.md): Either postDateFrom and postDateTo OR settledDateFrom and settledDateTo must be provided. (Note: Records will only be returned by the postDateFrom/To range if the transaction has settled.) For Authentication with this API, you must first obtain a token through https://docs.connexpay.com/reference/reporting-token. This endpoint is only accessible in Production.
- [Get Available Credit Report](https://docs.connexpay.com/reference/availablecreditreport.md)
- [Get Enhanced (Level 2 and Level 3) Travel Data](https://docs.connexpay.com/reference/getextendeddata.md): Retrieves enhanced data for travel-related transactions. This includes airline and hotel details, such as passenger names, flight numbers, hotel charges, etc. The data is paginated and can be filtered by various parameters. For Authentication with this API, you must first obtain a token through https://docs.connexpay.com/reference/reporting-token. This endpoint is only accessible in Production.
